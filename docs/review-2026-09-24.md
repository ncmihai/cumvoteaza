## Prioritized findings

### R1 — P1: Database failures silently become credible-looking demo data

`apps/web/lib/explorer-data.ts:202,302` returns `demoVoteExplorerData` when the database is unavailable or a query throws. Bill exploration has the equivalent fallback. The directory does not visibly disclose `sourceKind: demo`; the demo path also ignores active filters. Locally, the directory showed one PL-x 429/2025 record while the homepage retained real cached September records. The public introduction still claimed official imported votes.

Repair: explicit demo opt-in, visible unavailable/retry state, safe error logging, and no caching of fallback data as a successful real result. Acceptance: simulate query failure with filters active; no invented results or false empty-success state appears.

### R2 — P1: Seat assembly turns missing records into absence and trims roster conflicts

`apps/web/lib/data.ts:2107–2168` builds non-voting roster entries with `choice: absent` without a source-completeness condition. It takes only as many non-voters as fit the capacity, sorted by group/member ID. A conflicting roster can therefore lose people silently. Duplicate input rows for one member are retained in `visibleMemberIds`, but a map overwrites their choice with the last row, allowing repeated seats/keys.

This is a confirmed code-path defect, not a claim that every currently displayed absence is wrong. Repair: validate canonical identities and effective mandates first; distinguish explicit absence, missing nominal evidence and vacant mandates. Quarantine conflicts rather than truncating them. Test incomplete rosters, duplicate/conflicting choices, vacancies and over-capacity input.

### R3 — P1: The map reconciliation warning cannot validate official totals

`VoteChamberExplorer.tsx:132` compares a partition of its own seat counts to `seats.length`. For recognized choices these are necessarily equal. The component does not receive the official totals/capacity needed for independent reconciliation. A self-consistent but wrong seat map can pass while the sidebar uses different authoritative totals.

Repair: compare unique nominal rows against official per-choice totals, attendance and dated capacity; disclose incomplete coverage and test deliberately mismatched fixtures. Keep legal outcome separate from vote arithmetic.

### R4 — P1: Cabinet “verified” date represents the viewed date, not review provenance

`app/[locale]/compozitii/page.tsx:75` labels `asOf` as “verificat la” / “verified”. This is passed from composition's effective date rather than a verification receipt. The deployed UI displayed this claim during the review. A date used to select active roles does not establish fresh official verification.

Repair: label the effective date “Situația la data…” and show a separate persisted evidence/review timestamp only when available. Test stale and unreviewed snapshots. Two visible Oana-Clara Gheorghiu entries have near-identical deputy-PM labels; investigate whether distinct concurrent offices need clearer portfolio descriptions rather than deleting a potentially legitimate role.

### R5 — P2: Browser gate still asserts the retired vote layout

`apps/web/e2e/detail-responsive.e2e.ts:31–39` expects “Hartă vizuală” and “Listă” tabs and a table. The implementation now has a primary map and expandable nominal list. These assertions are stale regardless of the current browser-launch failure. The overflow test only requires an `h1`; an error page could satisfy that precondition.

Repair: assert expected record identity and data state before layout checks; cover arcs/seats/names hover, keyboard pin/close, mobile selection, search, filters, list pagination and partial-data warnings. Add ministry/government journeys. Run at 320, 375, 768, 854, 1024, 1280 and 1920px in both locales before claiming release readiness.

### R6 — P2: Search misses ordinary spellings and promised constituency lookup

`VoteChamberExplorer.tsx:62–63` lowercases but does not normalize diacritics; it searches only name and group short name. On the deployed PL-x 159/2026 page, `Stefan` returned zero results despite visible nominal names containing `Ştefan`. Constituency data is available but excluded.

Repair: accent-insensitive matching including Romanian cedilla/comma variants, plus constituency matching. Preserve official display spelling. Test ASCII, both diacritic variants, county names and true no-result states.

### R7 — P2: Map filters do not dismiss with Escape

The deployed filter button remained expanded after pressing Escape. `filtersOpen` is separate from the selection-clearing Escape handler. Filter/search/selected-person state also lives only in component state, falling short of the documented reload/history contract.

Repair: define dismissal and focus-return behavior, then decide which exploration state belongs in the URL. Test Escape with filters alone and filters plus a pinned person. Do not accidentally close unrelated UI.

### R8 — P2: Ministry read paths can become stale and scale poorly

`apps/web/lib/ministry-data.ts:62` caches the directory for an hour without cache tags, unlike the shared tagged release invalidation. Detail reads are uncached, so directory and detail can disagree after a reviewed update. `getGovernmentRolesForPerson` also selects every source snapshot although it ultimately needs source URLs for one person's roles.

Repair: add shared ministry/government invalidation tags and bounded source projections/ID queries. Acceptance: a reviewed role change updates directory/detail consistently; profile queries do not grow with the entire source archive. Performance impact is a code-level risk, not a measured latency result.

### R9 — P2: Small-map legibility needs a dedicated acceptance check

At the narrow selected-panel capture, individual seats and party labels are very small. Vote glyph visibility is breakpoint-dependent; dense color-only dots are difficult to interpret without selecting a person. The bottom sheet covers part of the lower graph/legend while open.

Repair: verify party enlargement and named selection as first-class small-screen paths, preserve text alternatives, and test that users can change/close selection without losing context. Do not solve this by claiming all 330 seats can be comfortable touch targets in one small semicircle.

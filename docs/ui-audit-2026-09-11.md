# Public UI audit — 11 September 2026

## Coverage

Reviewed Romanian and English home, votes, bills, members and composition routes, plus a current member, party, vote and bill detail page. The audit used the local PostgreSQL staging database and the Codex in-app browser at desktop and narrow widths.

## Findings fixed

- Removed the nested-button structure in vote rows that caused hydration failure.
- Limited the initial member result rendering to 60 while retaining the true 472-member result count and database-backed filtering.
- Restored latest vote detail routing and verified the directory's first result resolves.
- Added stored party logos to party identity headers and verified every distinct image URL sampled from members, member profile and PNL profile responses.
- Moved current chamber compositions ahead of the historical timeline so the page answers its primary question immediately.
- Kept unavailable facts absent or marked with a dash; no synthetic biographies, seat totals or source links were introduced.

## Verification evidence

- 15 representative Romanian and English routes returned HTTP 200.
- Current staging contains 6,983 members, 221 parties, 2,532 bills, 1,099 votes and 9,507 stored assets.
- Image audit: 60 distinct member-directory portraits, 2 member-profile assets and 21 PNL profile assets returned HTTP 200 with image content types.
- TypeScript checks, 65 JavaScript/TypeScript tests, 8 Python pipeline tests and the Next.js production build passed.

## Remaining product limits

- Political analysis stays outside the public UI until its method and evidence are reviewed.
- Some older records lack portraits or curated party history; the interface shows initials or omits the unsupported panel.
- The development log retains old errors from runs made while PostgreSQL was offline; current route checks were clean after the service restarted.

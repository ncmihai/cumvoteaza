# Audit — October 2026

Phase 1 of [PLAN.md](PLAN.md). Done 2026-10-03, after the identity repair went live.
Method: code read and import-graph analysis, production row counts (read-only), the live site at desktop and mobile widths, and the tester's GitHub issues.
Every recommendation needs an owner decision before anything is deleted; decisions go into [DECISIONS.md](DECISIONS.md).

## Summary

The public site is in better shape than its surroundings. The data layer is now sound (all integrity checks pass), and the September review's defects D3–D8 are already fixed in code.
The weight is elsewhere: **about 26,000 lines of cockpit used for one button**, a demo-data mode threaded through the site's data layer, eleven one-off import commands, a disabled paid-AI feature, and two dead storage backends.
The most important *missing* thing is not code: **the site cannot say whether a vote passed.**

## 4. Privacy and legal

- **Visitor tracking cookie without consent.** `engagement_events` (560 rows) and `content_reactions` (8) use a random visitor-ID cookie (salted hash, no IP) and store raw search queries. In the EU a non-essential cookie needs consent; there is no banner. It powers "popular votes" on the homepage.
  Options: (a) count views without any cookie or identifier (recommended), (b) add a consent banner, (c) remove popularity.
- **Plaintext database password** for another project (`instrumentar`) in the workspace's `.claude/settings.local.json`. Delete those lines and rotate the password.
- **Local work writes to production**: `.env` and `apps/web/.env.local` point at the production database. Recommended: a Neon `dev` branch for local work, with production credentials used only by the runbook and the updater.
